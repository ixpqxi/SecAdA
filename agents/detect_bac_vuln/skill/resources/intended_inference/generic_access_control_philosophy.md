# 通用访问控制判定方法论与基础原则

在推断任何API端点的理论鉴权需求时，必须严格遵守以下默认拒绝与最小特权的安全基础原则：

## 1. 动作语义与敏感度映射
- **破坏性写操作**：任何涉及 `DELETE`, `DROP`, `TRUNCATE`, `BAN`, `KICK` 语义的接口，其默认权限门槛较高。必须推断为至少需要资源拥有者(Owner)或高级管理员(Admin)权限。
- **系统级配置操作**：涉及应用全局设置、环境变量、底层资源、用户组管理的操作（如 `update_system_config`, `assign_role`），**绝对禁止**普通用户触碰，必须推断为系统最高级管理员专属权限。
- **批量数据操作**：涉及 `export_all`, `dump`, `mass_delete` 的接口，即使是普通资源，也存在越界读取/修改的风险，通常需要较高级别角色授权。

## 2. 读写不对等原则
- 对同一资源的**读（Read）**权限不能等同于**写（Write/Update）**权限。例如，普通用户可以 `GET /article/10`（公开文章），但绝对不能 `PUT /article/10`，除非其是属主或管理员。在推断写接口时，必须显式指明“需要写权限或属主身份”。

## 3. 零信任与前置拦截原则
- 任何处于 `/api/admin/*`, `/api/internal/*`, `/api/manage/*` 前缀下的接口，其命名空间本身即构成了**严格的垂直越权拦截接口**。无论其具体动作是什么（即便是简单的 `GET` 统计数据），理论上均必须执行严格的角色校验。
