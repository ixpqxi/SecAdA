# 常见误报模式库 (False Positive Patterns)

## 1. 虚构攻击场景 (The Impossible Precondition)
* **特征**：报告中的攻击链路在逻辑上通顺，但其触发的前提条件在系统中根本无法构造。
* **案例**：大模型认为某接口允许无权限访问，但系统的产品逻辑是：如果不勾选“读取”权限，该链接根本无法生成并存入数据库。

## 2. 分布式/微服务架构鉴权误判 (Desync vs. Real Auth)
* **特征**：大模型发现节点 A 同步权限给节点 B 失败，从而认为 B 拥有了非法权限。
* **事实**：在很多设计中，节点 B 的视图仅供展示，最终写操作仍需路由回拥有者节点 A。A 会进行最终的物理级鉴权。前端状态的 Desync != 越权漏洞。

## 3. UI 混淆 vs 安全边界 (Obfuscation vs. Boundary)
* **特征**：大模型看到某个接口绕过了 `hidden`、`preview` 等参数，获得了缩略图。
* **事实**：开发者明确注释这只是为了防止普通爬虫或用户随意下载的“防混淆”手段。在没有严格机密要求的公开分享场景，这属于产品特性妥协，不构成 Access Control Bypass。
