# 业务逻辑与鉴权漏洞审计指南 (Logic & Auth Flaws)

静态扫描工具无法理解业务，你需要代入“恶意用户”视角进行推理。

## 1. 越权漏洞 (IDOR / Broken Access Control)
- **审计特征**：代码中通过用户传入的 ID（如 `?user_id=123`, `order_id=456`）查询或修改数据。
- **水平越权**：同级用户互相操作。检查 `WHERE` 条件中是否缺少 `AND owner_id = {当前登录用户Session ID}`。
- **垂直越权**：低权限用户调用高权限接口。检查管理后台相关的 Controller 是否正确挂载了权限校验拦截器（如 `@RequiresRoles("ADMIN")`）。

## 2. 支付与交易篡改
- **审计特征**：涉及金额、数量、积分的逻辑运算。
- **风险点**：
  - **负数支付**：购买数量传入 `-1`，可能导致退钱。
  - **单价篡改**：前端提交的单价（Price）直接参与计算，而没有以商品 ID 去数据库校验真实价格。
  - **并发溢出**：利用多线程同时发起请求（条件竞争/Race Condition），在扣除余额的锁机制不严谨时实现一次余额多次消费。

## 3. 密码找回与登录安全
- **风险点**：
  - **验证码复用/爆破**：验证码校验后未销毁，或长度极短（如4位纯数字）且未限制尝试次数。
  - **客户端回显**：验证码直接放在了 HTTP 响应的 JSON 或 HTML 中。
  - **任意用户密码重置**：重置密码的最后一步提交时，不仅包含新密码，还包含可通过抓包修改的 `username` 字段。
  - **Response 状态值篡改**：前端仅根据后端返回的 `{"status": 1}` 就判断认证成功并跳转，未在服务端产生实质的 Session 授予。
